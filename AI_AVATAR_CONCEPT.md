## 2. 🧠 Концепция: AI Avatar Team для Syndi

### Основная идея

Когда два со-фаундера матчатся в Syndi — каждый получает **персонального AI-аватара** со своими навыками, характером и памятью. Аватары работают как команда: помнят контекст проекта, выполняют рутинные задачи, оценивают совместимость пары в динамике и координируют действия через MessageBus.

---

### 🔄 Как это работает (User Flow)

```
1. Онбординг
   └─ Пользователь указывает роль (builder/seller/operator/researcher),
      проходит MBTI + Энеаграмму, заполняет FounderProfile

2. Матчинг
   └─ Syndi вычисляет FounderFit score по Intent + Role + Tempo + WorkStyle + Big5
   └─ При совместимости выше порога → создаётся Match

3. Создание аватара при матче
   └─ AvatarFactory.create(founder_role, mbti, enneagram, big5)
   └─ ProfessionProfile назначается по роли фаундера
   └─ EmotionalCore инициализируется с чертами из Big5

4. Активация Trial Period (3 дня)
   └─ Аватар получает TaskManager с рутинными задачами по роли
   └─ AgentRouter настраивает режимы: советник → исполнитель → ментор
   └─ MessageBus связывает аватаров обоих фаундеров

5. Жизнь пары
   └─ Аватары помнят контекст (semantic_memory + dialog_memory)
   └─ Отслеживают динамику совместимости (evolve() при каждом взаимодействии)
   └─ Предупреждают о risk_flags из scoring
   └─ Telegram-уведомления через бот
```

```
│         │                             │             │
│  ┌──────▼───────┐          ┌──────────▼───────────┐ │
│  │  Avatar A    │◄────────►│     Avatar B         │ │

│         │                             │             │

│  │            Shared Memory Layer                 │ │
│  │  semantic_memory │ dialog_memory │ persistent  │ │
│  └────────────────────────────────────────────────┘ │
│                     PostgreSQL + Redis              │
└─────────────────────────────────────────────────────┘
```

**Ключевые компоненты:**

- **AvatarFactory** — создаёт аватара при матче, назначает ProfessionProfile по роли фаундера
- **EmotionalCore** — аватар меняет состояние (energy, happiness, curiosity, anxiety) в зависимости от активности пары; `evolve()` вызывается при каждом диалоге
- **AgentRouter** — автоматически переключает режимы: `советник` (стратегические решения) / `исполнитель` (рутинные задачи) / `ментор` (конфликтные ситуации)
- **MessageBus** — шина для координации аватаров двух со-фаундеров: синхронизация задач, совместное планирование, эскалация рисков
- **Память:** `semantic_memory` (долгосрочный контекст проекта и партнёра), `dialog_memory` (текущая сессия), `persistent_memory` (история пары)

### 🎯 Что аватар умеет делать для со-фаундера

- 🧠 **Помнит контекст** — проект, идею, договорённости с партнёром, историю решений
- ⚙️ **Выполняет рутину** — задачи из `ProfessionProfile.routine_tasks` по роли
- 📈 **Динамическая совместимость** — не только статичный FounderFit score, но и мониторинг drift'а ценностей в реальном времени через `evolve()`
- ⚠️ **Предупреждает о рисках** — эскалирует `risk_flags` из scoring (конфликт темпа, разные accountability-стили)
- 🔁 **Trial Period tasks** — структурированные задания на 3 дня для проверки совместимости пары на практике
- 💬 **Проактивные сообщения** — Telegram-уведомления: «Вы не общались с партнёром 2 дня — стоит синхронизироваться»

## 3. ⚡ Быстрые wins — что перенести прямо сейчас

### Win #1 — `ProfessionProfile` + `PROFESSION_REGISTRY`

**Что:** Заменить упрощённый `FounderProfile` в Syndi полноценными профилями профессий.

**Почему сейчас:** Минимальный риск — чистая замена структуры данных без изменения логики матчинга. Все 169 тестов должны пройти без изменений.

**Что даёт:** Каждый фаундер сразу получает `skills`, `routine_tasks` и `system_prompt` по роли. Основа для D1 (AvatarFactory).

**Оценка:** ~4 часа работы, 0 риска поломки scoring.

---

### Win #2 — `EmotionalCore` в Kristina-агент

**Что:** Добавить `EmotionalCore` (traits из Big5 + state: energy, happiness, curiosity) в существующий `agents/kristina.py`.

**Почему сейчас:** Kristina в Syndi уже принимает MBTI и энеаграмму из онбординга — Big5 уже есть в `scoring.py`. Это прямое подключение без новой инфраструктуры.

**Что даёт:** Аватар меняется в зависимости от диалога — `evolve()` после каждого сообщения. Тон ответов адаптируется под состояние (энергичный / задумчивый / поддерживающий).

**Оценка:** ~6 часов работы, 0 риска поломки матчинга.

---

### Win #3 — `AgentRouter` для Kristina

**Что:** Заменить keyword-based логику в `kristina.py` на `AgentRouter` из kristina-revolutionary, настроив три режима:
- `советник` — стратегические вопросы со-фаундеров
- `ментор` — конфликты и сложные ситуации в паре
- `исполнитель` — рутинные задачи по роли

**Почему сейчас:** Синди уже имеет контекст сессии через FastAPI — достаточно добавить маршрутизацию по типу запроса.

**Что даёт:** Кристина перестаёт быть «одним для всех» — каждый запрос получает правильный агент с правильным `system_prompt`.

**Оценка:** ~8 часов работы, низкий риск (тесты kristina.py легко обновляются).

## 4. 🌟 Визия продукта

Syndi AI — это не просто Tinder для со-фаундеров. Это платформа, где каждая команда получает **живую AI-команду**: персональные аватары работают 24/7, помнят контекст проекта и историю партнёрства, выполняют рутину по роли каждого фаундера, в реальном времени отслеживают drift совместимости и предупреждают о рисках задолго до того, как они станут конфликтом. Когда люди спят — аватары продолжают координировать задачи, синхронизировать приоритеты и готовить следующий день. Первые 90 дней со-фаундерства — самые хрупкие: именно здесь AI Avatar Team становится третьим участником команды, который не устаёт, не забывает договорённости и всегда на стороне пары.
